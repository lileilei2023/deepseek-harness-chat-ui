# DS Chat 项目改进方案（2026-09）

> 输入：`CLAUDE.md`、`TODO.md`、`docs/UI设计评审与优化方案.md`（七轮）、`docs/images/` 五张现状截图、
> `source/` 源码，以及 Harness `0.1.2-alpha.5` 检出中的宿主能力（`ui-primitives`、`ui-deliverables`、
> `ui-subagent`、`terminal`、`jobs`、`schedule`、`tool-fs-search`）。竞品部分来自对 Teamily、LobeHub Agent
> Team、Slack Agentforce、Teams Copilot、Poe、Character.ai、Codex 桌面版、ChatGPT / Claude 定时任务、Claude
> Cowork、WorkBuddy、豆包工作、Eigent、Flowith 公开资料的调研。
> 日期：2026-09-06。

## 一、判断

**概念成立，外观已过线，缺的是「活性」和「闭环」。**

把 Skill 变成可拉群的同事，这个差异点在 2026 年 9 月依然稀缺：直接对手只有 Teamily（闭源 SaaS），
国内大厂在 7 月 15 日《人工智能拟人化互动服务管理暂行办法》施行后集体下线了用户自建智能体，反而
把"本地、开源、可拉群"这条路让了出来。但今天打开一个群，除了头像和昵称，感受不到有人在干活；做完
一件事，产物拿不走；定时任务跑完了没人知道；终端不能用。这四件事决定了它是「演示好看」还是「每天打开」。

| 维度 | 分（/10） | 依据 |
| --- | ---: | --- |
| 概念与定位 | 8 | 拟人化 + 真可调用（软链）+ 跨项目小组 + 成员真并发，差异化是真的 |
| 美学 | 7 | 扁平、克制、明暗完整、令牌化；但没有签名元素，空状态与头部有结构问题 |
| 易用性 | 5 | 建群 / 加人 / @ 顺畅；群里「谁在干什么」不可见；终端与浏览器面板不可用 |
| 功能完备度 | 4 | 产物、自动化、终端三条链都只到「能看」，没到「能用」 |
| 工程健康 | 4 | 2400 行单文件、0 组件测试、整文档写状态、成员 id 不稳定 |

## 二、竞品与参照：各借一件事

| 产品 | 它做对的一件事 | 对 DS Chat 的含义 |
| --- | --- | --- |
| **Teamily AI**（2026-03 发布，07 公开） | agent 是群的一等成员；Studios（Web / Slides / Docs / Dashboards）把对话变成可 draft、annotate、fork 的交付物；跨群「活的记忆」 | 最直接的对手。我们赢在本地、开源、900+ 现成 Skill；输在「交付物是产品的一部分」与「记忆」 |
| **LobeHub Agent Team**（beta） | 编排模式 speak / broadcast / delegate / executeTask；口号「雇用、排班、汇报」 | 群聊要有显式的「发言模式」，不能只靠协调者的 system prompt 自觉 |
| **Slack Agentforce** | agent 像成员一样加入频道，@ 即召唤；**先私下给你看草稿，同意后再发到线程** | 「先私下看再公开」是群里 AI 发言的礼仪，可做成可选项 |
| **Teams Copilot agents** | 入群后出现在参与者列表并发一条欢迎消息；设计指南强调简短、少噪音 | 成员面板要常驻；入群要有仪式感 |
| **Poe 多 bot** | @ 任何 bot 进线程；**同一问题多 bot 并排比较** | 「对比模式」是拉群最自然的用例，底层并发子代理我们已经有 |
| **Character.ai 群聊** | 用户是主持人，点底部头像指定下一个发言者 | 点成员头像 = 定向发言，比打 @ 快 |
| **Codex 桌面版 Automations** | 触发器（定时 / webhook / 手动）、worktree 隔离、沙箱级别、`$skill` 挂载；结果进 **Triage 队列**（diff + 行内评论 + 通过 / 修订 / 拒绝）；无发现的运行自动归档 | 自动化必须有收件箱，否则跑了等于没跑 |
| **ChatGPT Scheduled**（2026-06 重上线）/ **Claude 定时任务** | 侧栏 Scheduled 区即收件箱，带未读点；任务页聚合指令 / 周期 / 状态 / 立即运行 / 最近历史；桌面通知 | 运行历史 + 未读 + 通知，三件缺一不可 |
| **Claude Cowork Artifacts** | 产物有独立视图、版本历史（比较 / 恢复）、按版本分享 | 产物要有版本，不只是「最后一份」 |
| **WorkBuddy / 豆包工作** | 任务模式左侧实时步骤面板；技能商店；「工作伙伴小队」；产物直接放到桌面 | 过程可视化 + 产物落到用户手里 |
| **Eigent**（CAMEL） | 每个 agent 一张实时任务卡；人类介入确认弹窗 | 成员状态卡是多 agent 产品的标配 |
| **Flowith Neo** | 画布上可见的 Recipe（子任务清单） | 任务拆解应可见、可点 |
| **微信 / Discord 惯例** | 在线状态点、「正在输入」、成员侧栏、群公告、置顶消息、@所有人、群主 / 管理员 | 我们借了外形，还没借活性 |

**合规注意。**《人工智能拟人化互动服务管理暂行办法》管的是「面向境内公众的持续性情感互动服务」。
DS Chat 是本地开发者工具，Skill 的人格只是同事身份，不在射程内。但两个设计默认值值得现在定下：
**AI 身份始终可见**（头像角标或资料页首行标注「AI 技能」），**文案不用陪伴 / 情感话术**（用「同事」
「成员」，不用「伙伴」「陪你」）。零成本的护栏，也让产品在企业环境里更好卖。

## 三、差距地图

**美学**

- 空状态是一张大卡片 + 一个头像，而这是一个 4 人群（`deepseek-harness-chat-ui-main.png`）。
- 头部是浮在右上角的药丸，与会话列脱开；信息与侧栏当前行重复。
- 房间行没有成员数时渲染了一个 `—` 占位（「山楂」「普通对话」两行）。
- 成员简介直接截断原始英文 SKILL.md description（建群弹窗），拟人化到这里断了。
- 没有任何「活」的元素：没有状态点、没有正在输入、没有进度。

**易用性**

- 群里看不到谁在干什么。宿主 `ui-subagent` 已按父会话维护子代理目录（running / inactive、tokens、
  时长），但没接进房间。
- 定向发言只能手打 @。
- 终端一条命令一次快照，不能中断、不能交互（`TODO.md` P0）。
- 浏览器面板默认地址硬编码为一个打不开的端口。
- 工作台状态不持久。

**完备度**

- 产物：mtime 启发式、不可下载 / 新标签打开、无版本。
- 自动化：无运行历史、无失败可见、无通知、无手动触发。
- 成员 id 不稳定，三处按名回退。

## 四、方案：四个里程碑

每一项写清：做什么、怎么做（具体到宿主 API）、完成标准、量级（S 1–2 天 / M 3–5 天 / L 1–2 周）。

### M1 · 止血（约 1–2 周）：让今天不能用的三样能用

**1.1 终端改成流（P0，量级 M）**

- 怎么做：客户端轮询宿主 `terminals.read(agent, id, { offset, count })`。它本来就是分页的
  （返回 `lineBegin / lineEnd / totalLines / truncated`），运行中 250–300 ms 一次、空闲指数退避到 2 s。
  渲染换成宿主 `ui-primitives` 的 `TerminalBlock` + `ansi.ts`（Anser 解析，颜色映射到主题令牌，明暗
  都对，零新依赖）。Ctrl-C 接 `session.signal('SIGINT')`（宿主契约有 SIGINT / SIGTERM / SIGKILL /
  SIGTSTP / SIGHUP）。输入框加本地历史（↑ ↓）。`truncated` 时显示「已截断 · 加载更早」，用 `offset` 翻页。
- 做不到的：PTY 尺寸。`TerminalSpawnRequest` 只有 `type / name / cwd`，契约里没有 resize。向 Harness
  提 issue；界面先按固定列宽渲染并在面板上说明。
- 完成标准：`npm install` 期间界面持续增长；`git log --oneline --color` 无乱码；Ctrl-C 能停掉
  `sleep 100`；超出缓冲显示截断提示并可加载更早。

**1.2 产物来源从 mtime 换成因果（P1，量级 M）**

- 怎么做：宿主 `ui-deliverables` 已经从 `write` / `edit` / `str_replace_editor` 的成功调用里折叠出每
  回合的产物清单（`deliverablesDefinition`），渲染在 `conversation.chat.turnTail`。我们消费同一份定义，
  按 turn 把路径、消息 id、发言成员写进 `RoomSession.artifacts`；mtime 扫描降级为「其它变动」。
- 完成标准：产物面板每一项都能点到「由哪条消息、哪位成员产生」；你在别的窗口改的文件不再混入。

**1.3 产物拿得走（P1，量级 S）**

- 怎么做：「在 Finder 中显示」走 `session.openWorkspacePath`（先用 `canOpenWorkspacePath` 探测，
  loopback 才可用，与宿主自己的行为一致）。「下载」用 Blob URL：文本走已有 `readFile`；二进制需要宿主
  一条受限静态路由，先做文本。HTML 报告「新标签打开」用 `URL.createObjectURL`。
- 完成标准：一份 47 KB 自包含 HTML 报告可下载、可新标签打开、可定位到文件夹。

**1.4 浏览器面板（P2，量级 S）**：默认地址清空，提示「输入本地开发服务器地址」，按 workspace 记住上次地址。

**1.5 成员改存 Skill 名（P3 根治，量级 M）**：状态 v2 → v3 迁移，`memberIds` 变 `memberNames`，
删掉 `memberContact()` / `ensureLinked()` / `memberSkillName()` 三处按名回退。

### M2 · 让群活起来（约 2–3 周）：差异化的核心

**2.1 常驻成员面板（量级 L）**

- 每个成员一行：头像、昵称、一句职能、状态点（空闲 / 工作中 / 等你确认）、正在做什么（子代理标题）、
  本回合耗时。
- 数据来源：宿主 `ui-subagent` 的子代理目录（mode、running / inactive、`tokenUsage`、时长）。协调者
  给每个成员起的子代理提示里已写明「先加载 <成员名>」，据此把子代理映射回成员。
- 挂载：通过 `conversation.view` 槽位注册为会话视图环的一个 tab（宿主 `ui-trajectory` 就是这么挂的），
  或作为右侧可折叠抽屉。
- 完成标准：三人并发时三个状态点同时亮；任一子代理结束，状态点熄灭且该成员的气泡出现。

**2.2 「正在工作」条（量级 S，依赖 2.1 数据层）**：输入框上方一行 `麦麦 正在整理数据 · 咔咔 正在搜索`，
借 Slack / Teams 的 typing indicator。挂 `conversation.input.dock` 或 `conversation.composer.bar`。

**2.3 群公告与置顶（量级 M）**

- `ChatRoom` 增加 `notice`（用户可见、可编辑、注入 system prompt）；消息级「置顶」把一条消息钉在头部。
- 这是「跨会话记忆」的最低成本替代：不承诺 Teamily 式记忆系统，但让团队的约定有地方放。

**2.4 定向发言与广播（量级 S）**：点成员头像 = 输入框插入 `@昵称 `（Character.ai）；`@所有人` = 广播模式，
协调者必须让每位成员各答一次（LobeHub broadcast）。

**2.5 对比模式（量级 M）**：「让 N 位成员各答一次」——一次提问，N 个子代理并发，结果并排卡片，
用户点「采纳」把某一答案作为后续上下文（Poe）。

**2.6 入群仪式与身份可见（量级 S）**：加成员时房间里出现一条系统消息「麦麦 加入了群聊 · 擅长
1Password CLI」（Teams 模式）；头像角标或资料页首行标注「AI 技能」。

**2.7 简介本地化（量级 S）**：`bio` 从原始 description 截断改为「一句话职能」——目录扫描时按规则取
首句，英文来源在 UI 里标注语言，用户可改。不调模型。

### M3 · 交付闭环（约 2–3 周）

**3.1 产物版本与 diff（量级 M）**：同一路径多次产生 → 版本列表；相邻版本 diff 复用 `DiffView`
（或宿主 `DiffBlock`）；「恢复到此版本」= 写回文件，二次确认。

**3.2 自动化收件箱（量级 L）**

- 运行记录：新增 `automationRuns[]`（runId、automationId、sessionId、startedAt、finishedAt、status、
  summary、artifacts）。
- 侧栏「自动化」入口显示未读数；自动化页改为任务页：指令 / 周期 / 状态 / 立即运行 / 最近运行。
- 失败可见：`status = failed` + 错误摘要 + 「重试」。
- 桌面通知：浏览器 `Notification` API（首次请求权限），点击进入对应会话。
- 触发方式加「手动」；周期规则从 `every:N(m|h|d)` 扩到 `daily@09:00`、`weekdays@09:00`。

**3.3 工作台状态持久化（量级 S）**：展开目录、打开的文件标签、终端标签、面板宽度，按 roomId 存
localStorage。

**3.4 目录树虚拟化 + 搜索走 ripgrep（量级 M）**：宿主 `tool-fs-search` 已用 `@vscode/ripgrep` 经
`subprocess` 跑 `rg`，复用同一 seam，结果流式返回；树用固定行高的窗口渲染。

### M4 · 美学与工程（穿插进行）

**4.1 视觉修正（按截图逐条）**

- 空状态：单头像换成成员阵列（最多 4 张）+ 每人一句职能 + 「@ 谁开始」；卡片降为无边框区块；去掉
  左上角的绿色径向渐变——它是页面上唯一的装饰，来源不明。
- 头部：浮动药丸改为会话列顶部的固定条（Teamily / Slack 一致），标题左、动作右，成员数与协调者进副行。
- 房间行：没有成员数的行不渲染占位 `—`。
- 简介：见 2.7。
- 签名元素：状态点与「正在工作」条用强调色 + 1.2 s 脉动（`prefers-reduced-motion` 时静止）。这是
  整个界面唯一允许的动效，因此它就是签名。
- 一致性：图标统一用宿主 `ui-primitives/icons`；新面板圆角按 6 / 8 / 10 / 12 / 16 / 20 尺度复查；
  hairline 0.5 px。

**4.2 无障碍**：新消息与状态条用 `aria-live="polite"` + `aria-atomic="false"`；成员面板可键盘遍历；
对比度检查纳入 `npm run check`。

**4.3 工程**

- 拆 `SkillContactsBrowser.tsx`：`roster/`（侧栏与联系人）、`room/`（头部、成员面板、对比模式）、
  `workbench/`（文件、终端、产物、浏览器）、`automation/`。目标单文件 < 600 行。
- 组件测试：Testing Library + happy-dom，覆盖房间列表、建群弹窗、成员面板、自动化列表（≥ 20 个）。
- 视觉回归：把 `shoot.mjs` / `record.mjs` 收进 `scripts/`，生成截图 diff。
- 状态写入：`putSkillChatState` 改为按集合分文件（rooms / roomSessions / personas / automations /
  automationRuns），或至少 debounce + 差量。

## 五、不做的事

- 独立图标导航栏——宿主只开放 `sidebar.workspaces` 等槽位（评审 10.1）。
- 常暗皮肤——第七轮已撤回，理由成立。
- Teamily 式跨群记忆系统——先用群公告 + 资料页承接，等宿主 `context` / `compaction` 开放可复用的
  记忆能力再接。
- 复刻 IDE——工作台的职责是「拿到交付物」，不加编辑器、不加 git 面板。
- 情感 / 陪伴向的人格设定。

## 六、验收指标

| 里程碑 | 指标 |
| --- | --- |
| M1 | 终端首次输出 < 500 ms，长命令持续刷新；产物 100% 可追溯到消息；HTML 报告可下载 / 新标签打开 |
| M2 | 并发时成员状态点实时；点头像即 @；群公告可在 system prompt 中验证 |
| M3 | 每次自动化运行有记录；失败 100% 可见；未读数正确；桌面通知到达 |
| M4 | 拆分后最大文件 < 600 行；组件测试 ≥ 20；对比度全部 ≥ 4.5:1；截图脚本入库 |

## 七、第一周就动手

1. 终端轮询 + ANSI（1.1）——用宿主现成的 `TerminalBlock`，两天可见效果。
2. 产物接 `deliverablesDefinition`（1.2）——把启发式换成因果，是 M3 的地基。
3. 成员面板的数据层（2.1 前半）——先把子代理目录映射到成员，UI 后补。

## 实施进度（2026-09-06）

| 里程碑 | 状态 |
| --- | --- |
| M1 止血 | 全部完成。终端改流、产物因果溯源、产物可拿走、浏览器面板默认地址、成员改存 Skill 名 |
| M2 让群活起来 | 除对比模式的并排渲染外全部完成。成员面板、正在工作条、群公告、点名 @ 与 @所有人、入群提示、一句话简介 |
| M3 交付闭环 | 全部完成。产物版本与 diff（走 git）、自动化收件箱与钟点周期、工作台状态持久化、ripgrep 搜索、目录树虚拟化、文件树写操作 |
| M4 美学与工程 | 视觉修正、无障碍、状态分文件写、工作台拆分、组件测试、截图脚本入库完成。**侧栏与房间尚未拆分；三张截图欠一次带模型的重拍** |

三处偏离原计划，都记在 `TODO.md` 里：

- **ripgrep 从 PATH 取，不是复用宿主打包的那份。** 引用 `dsh-tool-fs-search` 会连带
  拖进它的传递依赖，插件从 GitHub 装到别处时 Node 直接 `ERR_MODULE_NOT_FOUND`，
  整个 Harness 起不来。取不到 `rg` 时回退到原来的遍历。
- **ANSI 解析器是插件自带的。** 客户端 bundle 纯度门禁禁止跨插件的值导入，宿主那份
  在 `ui-primitives` 内部，不在公开导出上。
- **对比模式只做到广播。** 并排渲染要接管宿主的流节点渲染，代价是重新实现思考与
  工具调用的富渲染——第四轮评审已经因为同样的原因放弃过一次折叠。
- **产物版本走 git，不自己存快照。** 状态文档本来就整份读写，把文件内容塞进去会
  更糟；仓库保存着同样的东西，而且保得更对。代价是非仓库工作区没有历史可看。
